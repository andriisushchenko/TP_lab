# Візуалізація: дерево виводу (VIS-01) і порівняння з AST (VIS-02)

`sipl tree` будує **дерево синтаксичного виводу** (parse tree) програми за правилами граматики [sipl.lark](../src/sipl/grammar/sipl.lark), як у практичній роботі 1.

На відміну від AST (`sipl parse`), у дереві виводу є:

* усі нетермінали, навіть ті, що мають одного нащадка: `<stmt> → <assign>`, `<aexpr> → <aterm> → <afactor>`;
* усі термінали: `begin`, `end`, `;`, `:=`, дужки, ключові слова.

Якщо прочитати листки дерева зліва направо, вийде сама програма (без пробілів).

## Як будується

Дерево будує окремий парсер Lark `tree_parser` у [grammar/\_\_init\_\_.py](../src/sipl/grammar/__init__.py) на **тій самій** граматиці. Перед цим із тексту граматики прибираються:

* `?` перед правилами — щоб вузли з одним нащадком не згорталися;
* `-> add`, `-> num` та інші — щоб вузли називалися нетерміналами граматики.

Також увімкнено `keep_all_tokens=True`, щоб у дереві лишалися всі термінали. Розбір не змінюється, змінюється лише форма дерева.

Спершу програма перевіряється звичайним `parse`, тому синтаксичні помилки мають той самий вигляд, що й в інших командах.

## Формати

```bash
sipl tree examples/gcd.sipl                          # текст
sipl tree examples/gcd.sipl --json                   # JSON
sipl tree examples/gcd.sipl --format dot -o gcd.dot  # Graphviz DOT
sipl tree examples/gcd.sipl --format svg -o gcd.svg  # SVG-картинка
```

### Text

```
<program>  [1:1-4:4]
  begin  [1:1-1:6]
  <stmt_seq>  [2:3-3:45]
    <stmt>  [2:3-3:45]
      <while_stmt>  [2:3-3:45]
        while  [2:3-2:8]
        <bexpr>  [2:9-2:18]
...
```

`<...>` — нетермінал, без дужок — термінал. Для змінних і чисел видно й категорію: `NAME A`, `NUMBER 1`.
`[рядок:колонка-рядок:колонка]` — фрагмент вихідного коду, з якого вивівся вузол.

### JSON

```json
{"symbol": "assign", "text": "R := 1",
 "span": {"line": 2, "column": 3, "end_line": 2, "end_column": 9},
 "children": [
   {"symbol": "NAME", "text": "R", "span": {...}},
   {"symbol": ":=", "text": ":=", "span": {...}},
   {"symbol": "aexpr", "text": "1", "span": {...}, "children": [...]}
 ]}
```

| Поле | Значення |
|---|---|
| `symbol` | нетермінал (`assign`, `aexpr`, ...), `NAME`/`NUMBER` або сам термінал (`begin`, `:=`) |
| `text` | фрагмент вихідного коду, з якого вивівся вузол |
| `span` | позиція фрагмента (рядки й колонки з 1, кінець не включно) |
| `children` | лише в нетерміналив; нащадки зліва направо |

### DOT

Текст для [Graphviz](https://graphviz.org/): нетермінали — овали, термінали — прямокутники.
У `tooltip` кожного вузла записані позиція і фрагмент коду. Картинку з DOT можна отримати так: `dot -Tsvg gcd.dot -o gcd.svg`.

### SVG

Картинка без сторонніх програм. Нетермінали сині, термінали червоні.
Якщо навести мишку на вузол у браузері, з'явиться підказка з позицією та фрагментом коду.

Розміщення: кожен листок отримує власне місце по горизонталі (зліва направо в порядку тексту), а батьківський вузол стає посередині над своїми нащадками; рівень вузла відповідає його глибині в дереві.
## Порівняння Parse tree ↔ AST (VIS-02)

```bash
sipl compare examples/gcd.sipl -o gcd.html   # HTML-сторінка, відкрити в браузері
sipl compare examples/gcd.sipl --json        # обидва дерева й статистика в JSON
```

Сторінка показує поряд два окремі подання тієї самої програми:

* **Parse tree** — конкретний синтаксис: кожне правило граматики й кожен термінал (те саме, що `sipl tree`);
* **AST** — абстрактний синтаксис: лише вузли з [ast.py](../src/sipl/ast.py) (`Assign x`, `BinOp +`, `While`, ...).

Обидва дерева намальовані тим самим SVG-кодом, що й `sipl tree --format svg`.

Над деревами є таблиця: кількість вузлів і глибина кожного дерева, а також вузли parse tree, яким в AST не відповідає жоден вузол з тим самим фрагментом коду. Зазвичай це `begin`, `end`, `;`, `:=`, дужки, ключові слова та ім'я змінної зліва від `:=` (в AST воно лише рядок усередині `Assign`).

**Інтерактивність.** Кожен вузол обох дерев має атрибут `data-span` з позицією свого фрагмента. Якщо навести мишку на вузол, підсвітяться всі вузли обох дерев із тим самим фрагментом. Наприклад, `BinOp -` в AST і `<aexpr>` для `A - B` у parse tree. Так видно, у який вузол AST «згорнувся» ланцюжок правил граматики.

### JSON

| Поле | Значення |
|---|---|
| `tree` | parse tree у форматі `sipl tree --json` |
| `ast_tree` | AST у тому самому форматі (`symbol`, `text`, `span`, `children`); `symbol` — ім'я класу та прості поля вузла: `"BinOp +"`, `"Var x"` |
| `comparison` | `{"parse_tree": {"nodes", "depth"}, "ast": {"nodes", "depth"}, "only_in_parse_tree": [...]}` |

Для `Seq` фрагментом є код від першого до останнього оператора послідовності. Для всіх інших вузлів AST у parse tree є вузол з тим самим фрагментом коду (це перевіряється тестами).
