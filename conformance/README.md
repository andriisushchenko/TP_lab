# Conformance suite для SIPL

Набір програм SIPL з очікуваним результатом: AST, кінцевим станом або помилкою.
Він не імпортує код цього репозиторію. Скрипт запускає реалізацію як зовнішню команду й порівнює її JSON-вивід з очікуваним, тому так можна перевірити будь-яку реалізацію SIPL.

## Запуск

```bash
python conformance/run.py sipl
python conformance/run.py python -m sipl
python conformance/run.py java -jar other-sipl.jar
```

Після `run.py` іде команда, що запускає реалізацію (разом з аргументами).
Для кожного тесту друкується `PASS` або `FAIL` (з очікуваним і отриманим результатом), а в кінці — підсумок `N/M passed`.

| Код завершення | Значення |
|---|---|
| 0 | усі тести пройшли |
| 1 | є хоча б один `FAIL` |
| 2 | команду не передано або її не вдалося запустити |

## Що має вміти реалізація

Ті самі команди, що й `sipl` (див. [docs/cli.md](../docs/cli.md)):

```
КОМАНДА parse ФАЙЛ --json
КОМАНДА run ФАЙЛ [ЗМІННА=ЧИСЛО ...] --json
```

Вивід — один JSON-об'єкт у stdout у кодуванні UTF-8:

* `parse` → `{"ast": ...}`, формат вузлів AST описано в [docs/cli.md](../docs/cli.md);
* `run` → `{"state": {"змінна": число}}`;
* помилка → `{"error": {"kind": "syntax" | "runtime", "line": ..., "column": ...}}`.

Ліміт ітерацій циклів за замовчуванням має бути скінченним: тест `runtime_infinite_loop` чекає на помилку виконання.

## Формат тесту

Один тест — один файл `cases/ІМ'Я.json`:

```json
{
  "source": "begin R := 1; while Y > 0 do begin R := R * X; Y := Y - 1 end end",
  "input": {"X": 2, "Y": 3},
  "expect": {"state": {"X": 2, "Y": 0, "R": 8}}
}
```

| Поле | Обов'язкове | Значення |
|---|---|---|
| `source` | так | текст програми SIPL |
| `input` | ні | початковий стан `{"змінна": число}`; передається як `ЗМІННА=ЧИСЛО` |
| `expect` | так | рівно один із ключів `ast`, `state` або `error` |

Як перевіряється `expect`:

| Ключ | Яка команда запускається | Що порівнюється |
|---|---|---|
| `ast` | `parse` | AST повністю, але без полів `span` |
| `state` | `run` | кінцевий стан повністю (порядок змінних не важливий) |
| `error` | `run` | лише ті поля `error`, що вказані в тесті (`kind`, `line`, `column`) |

Текст повідомлення про помилку не порівнюється: різні реалізації можуть формулювати його по-різному.
Позиції (`line`, `column`) рахуються від 1.

Приклад тесту на AST:

```json
{
  "source": "begin x := -5 end",
  "expect": {"ast": {"type": "Program", "body": {"type": "Assign", "name": "x", "expr": {"type": "Num", "value": -5}}}}
}
```

Приклад тесту на помилку:

```json
{
  "source": "begin x := 1 div 0 end",
  "expect": {"error": {"kind": "runtime", "line": 1, "column": 12}}
}
```

## Імена тестів

Префікс показує, що перевіряється: `ast_*`, `state_*`, `syntax_*` (синтаксичні помилки), `runtime_*` (помилки виконання).
Щоб додати тест, достатньо покласти новий `.json` у `cases/` — `run.py` підхопить його сам.
